### 数据流
<img src='./image-2.png' align=right width=200>

数据流表示数据的流动情况，用带有名字的具有箭头的线段表示，名字称为数据流名，表示流经的数据。流入或流出数据存贮的数据名称可以省略。
### 数据流的使用约定
- 数据流上必须标出名字，名字应能反映数据流的含义，流入或流出数据存贮的数据名称可以省略，因为文件本身就足以说明数据流。
- 数据流不允许同名。
- 两个数据流在结构上相同是允许的，但必须体现人们对数据流的不同理解。
- 两个加工之间可以有几股不同的数据流，这是由于它们的用途不同，或它们之间没有联系，或它们的流动时间不同。

### 分层数据流图（例）
为提高设备利用率和降低设备的故障率，某公司需要开发一个设备管理系统，对公司的所有设备的基本资料和日常维护进行管理。该系统应包含如下功能：
（1）维护公司所有设备的基本资料，能够生成设备台账、设备结构清单和设备维修计划等报表文件；
（2）按照设备的检修要求，对设备进行定期检修；
（3）生产部门在使用设备过程中遇到故障时，能够生成报修单，提交设备管理部门进行维修，并对维修情况进行管理；
（4）设备维修的费用上报公司财务部门。

设备的基本资料包括设备的名称、编号、使用部门、存放地点等。显然，当购进新的设备时，这些信息都需要由设备管理部门进行输入。而且，当设备的某一项属性（如设备的存放地点）发生变化时，需要对设备信息进行更新。因此，需要一个管理设备基本信息的加工，用于维护公司的设备信息。当设备管理部门在录入或修改完设备的基本资料后，这些资料信息就更新进入系统的设备信息文件中。

生产部门在使用设备过程中，遇到设备故障时，将通过报修处理向系统提交报修单，系统通过读取报修单来启动维修过程。


系统要有一个加工来处理维修信息，如根据报修单和设备信息启动设备维修，根据设备信息，启动设备检修，并最终生成维修记录上报维修费用。

为了能生成一系列的报表，需要定义一个专门用来生成报表的加工，称报表管理。它通过读取设备信息和设备维修记录信息生成各种报表。

#### 结构化语言写的加工的说明
结构化语言是一种比自然语言精确，比形式化语言灵活易懂的语言。它没有严格的语法，它的结构通常分为内、外两层。 外层负责描述控制结构，如顺序、选择、循环等信息。 内层负责描述具体的加工信息，内层一般可以用更接近自然语言的语句书写。其一般的特点为：
- 只使用祈使句，它能明确地表达“做什么”
- 名词尽量是数据词典中的词
- 不要用形容词、副词等修饰语
- 可以用一般的数值、逻辑运行符，如＋－×/ and or等用户容易理解的符号。

## 结构化设计
### 软件设计阶段的任务
对软件解决问题的方案和具体方法进行建模，并使用**程序结构图**和**程序流程图**等模型描述程序的执行过程。
### 模块化设计设计原则
- 模块完成独立的功能
- 符合信息隐蔽和信息局部化原则
- 模块间关连和依赖程度尽量小
### 模块的耦合性
两个模块之间的耦合有6种形式，按照耦合程度由低到高排列为：**数据耦合、标记耦合、控制耦合、外部耦合、公共耦合、内容耦合**。
![alt text](image-14.png)

**什么叫标记耦合**
假设你去快递站拿快递，工作人员只需要核对你的名字和手机号。

理想的做法（数据耦合）：你直接口头告诉他你的名字和手机号。他拿到需要的信息，把快递给你。

标记耦合的做法：你把你的整个户口本和个人详细体检报告直接甩给了他。他翻开资料，确实从中找到了你的名字和手机号，但同时他也接触到了你的家庭住址、病史和家庭成员信息——这些都是他根本不需要的东西。

在这里，你和快递员之间就形成了“标记耦合”：你传了一个“大包裹”，但他只用了里面的两个“小物件”。

**什么叫控制耦合**
假设你要打车去机场。

好的做法（数据耦合）：你上车对司机说：“师傅，去机场（传递数据）”。至于走哪条路、怎么避开拥堵、什么时候换挡，全由司机自己决定。

控制耦合的做法：你上车对司机说：“师傅，前方路口左转，然后挂二挡，踩油门，看到红绿灯再踩刹车……”

在这种情况下，你不仅仅是给司机提供了一个目的地，你还在控制司机开车的内部操作流程。这就形成了控制耦合。

典型的控制耦合
```java
// 调用方通过 isVIP 这个布尔值，直接指挥函数内部走哪条分支
void calculatePrice(double amount, boolean isVIP) {
    if (isVIP) {
        System.out.println("VIP客户，打8折：" + (amount * 0.8));
    } else {
        System.out.println("普通客户，原价：" + amount);
    }
```

在Java中，`System.out.println`就是打印输出。

如何修正（拆分功能，消除控制耦合）
```java
// 把不同的逻辑拆分开，把控制权交还给调用方自己去判断
void calculateVipPrice(double amount) {
    System.out.println("VIP客户，打8折：" + (amount * 0.8));
}

void calculateNormalPrice(double amount) {
    System.out.println("普通客户，原价：" + amount);
}
```
### 模块的内聚性
内聚性是指一个模块内部各组成部分之间（如语句之间或语句段之间）的联系的紧密程度。

内聚性从高到低有7种：**功能内聚、顺序内聚、通信内聚、过程内聚、时间内聚、逻辑内聚、偶然内聚**。

#### 偶然内聚
如果一个模块的内部各组成部分的处理动作彼此没有任何联系，则称为偶然内聚。往往因为有多个模块有一段程序是相同的，为了节省程序量，而把这一段程序作成一个模块，而实际上这段程序内部的各部分没有什么联系。

![alt text](image-15.png)
#### 逻辑内聚
如果一个模块内部的各组成部分的处理动作在逻辑上相似，但功能都彼此不同或无关，则称为逻辑内聚。
![alt text](image-16.png)
#### 时间内聚
模块完成的功能必须在同一时间内执行，这些功能只因时间因素关联在一起。
初始化系统模块、系统结束模块、紧急故障处理模块等
#### 过程内聚
如果一个模块内各组成部分的处理动作各不相同，彼此也没有联系，但它们都受同一个控制流支配，决定它们的执行次序，称为过程内聚。
![alt text](image-17.png)
![alt text](image-18.png)

#### 通信内聚
如果一个模块内各组成部分的处理动作都使用相同的输入数据或相同的输出数据，称为通信内聚。

![alt text](image-19.png)

#### 顺序内聚
如果模块内一个内部成分的输出是另一个内部成分的输入，则属顺序内聚。也就是说，模块中一个成分依赖于另一个成分。

![alt text](image-20.png)
#### 功能内聚
一个模块仅包括为完成某个功能所必须的所有成分，即模块所有成分共同完成一个功能，缺一不可 ，则成为功能内聚。内聚性最强

## 面向对象开发技术
### 对象模型要素
面向对象模型有4个主要要素：
**抽象、封装、模块化、层次结构**
面向对象模型有3个次要要素：
类型、并发、持久
#### 各要素定义（能根据定义写出来要素）
- **抽象**描述了一个对象的基本特征，可以**将这个对象与所有其他类型的对象区分开来**，因此提供了清晰定义的概念边界，但它与观察者的视角有关。
- *抽象是从众多的事物中抽取出共同的、本质性的特征，而舍弃其非本质的特征。例如苹果、香蕉、生梨、葡萄、桃子等，它们共同的特性就是水果。得出水果概念的过程，就是一个抽象的过程。（来自百度百科）*
- **封装**：是一个过程，它分隔构成抽象的结构和行为的元素，封装的作用是**分离抽象的概念接口及其实现**。
- **模块化**是一个系统的属性，这个系统被分解为一组**高内聚、低耦合的模块。**
- **层次结构**是抽象的一种**分级或排序**。
- **类型**是**关于一个对象的类的强制规定**，这样一来，不同类型的对象不能够互换使用，或者至少它们的互换使用受到非常严格的限制。
- **并发**是一种属性，它**区分主动对象和非主动对象**。
- **持久**是对象的一种属性，利用这种属性，对象跨越**时间**（例如，当对象的创建不存在时，对象仍然存在）和**空间**（例如，对象的位置从它被创建的地址空间移开，存入数据库）而存在。
### 对象的本质
一个对象是一个具有**状态、行为、标识符**的实体
### 类之间的关系
- **继承关系**：一般/特殊关系，表示“**是一种**”关系。例如：玫瑰是一种花，这意味着玫瑰类是花类的子类。
- **聚合关系**：整体/部分关系，表示“**组成部分**”关系。例如：花瓣不是一种花它是花的一个组成部分。
- **关联关系**：一种语义上的依赖关系，如果没有这层关系，这些类就毫无关联了。如飘虫和花之间的共生关系，飘虫保护花免遭害虫侵害，花为瓢虫提供食物来源。
- **依赖关系**：处于这种关系一端的元素以某种方式依赖于处于另一端的元素。**如果其中一个元素发生了改变，可能会影响到另一种元素。**

#### 活动
状态框里的活动分为do, entry和exit，一般就只用到do

do活动指某个状态内持续的动作，用`do/活动名`表示
entry指进入一个状态时，执行某个动作，用`entry/活动名`表示
exit指退出某个状态时，执行什么动作，用`exit/活动名`表示
#### 示例1
汽车倒车雷达开始于闲置状态，当汽车挂倒挡倒车，雷达进入工作状态，检测车后障碍物的距离；当车距离障碍物小于1.2米时，发出低频声音警告的预备报警；当车距离障碍物小于0.6米时，发出高频声音警告的紧急报警；汽车挂前进档或者空挡，雷达进入闲置状态。

```mermaid
stateDiagram-v2
    direction LR
    state "汽车倒车雷达" as Radar {
        direction LR
        [*] --> 闲置
        闲置 --> [*]
        state "工作" as Working
        Working: do/检测车后障碍物距离
        state "预备报警" as Warning
        Warning: do/发出低频声音警告
        state "紧急报警" as Emergency
        Emergency: do/发出高频声音警告
        闲置 --> Working: 挂倒挡倒车
        Working --> Warning: 检测距离 [距离 < 1.2m]
        Warning --> Emergency: 检测距离 [距离 < 0.6m]
        Working --> 闲置: 挂前进档或空挡
        Warning --> 闲置: 挂前进档或空挡
        Emergency --> 闲置: 挂前进档或空挡
    }
```

你可能会看到把`检测距离[距离<1.2m]`直接写成`距离小于1.2米`或者`when(距离<1.2m)`等五花八门的写法，经过我的研究，结论是你想怎么写怎么写。
记得把标题写到左上角。
